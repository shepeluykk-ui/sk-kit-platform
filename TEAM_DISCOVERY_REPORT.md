## Executive Summary

SK-КИТ — работающее приложение строительного контроля на Express + React + SQLite с реально
работающим backend-слоем авторизации (62/62 теста проходят на чистой БД). Основные проблемы
сосредоточены **не в backend-логике**, а в трёх зонах:

1. **Фронтенд систематически рассинхронизирован со схемой данных.** 71 ошибка `tsc` в 9 живых,
   замонтированных компонентах. Это не «шум типов»: экран рейтинга подрядчиков, блок просроченных
   дефектов на дашборде и ИИ-анализ проекта фактически работают с `undefined`.
2. **Мобильный контур содержит фиктивную функциональность.** Офлайн-очередь без синхронизации,
   подстановка несуществующего фото как доказательства, отправка дефекта без проверки результата.
3. **Периметр аутентификации имеет дыру.** `POST /api/ai/chat` доступен анонимно и при пустом
   `documents` подставляет документы проекта `proj-1` в промпт, возвращая результат вызывающему.

Отдельно: развёрточный контур (Docker, CI/CD, PostgreSQL) в текущем виде **нерабочий** —
в нём три независимых дефекта, каждый из которых по отдельности блокирует запуск.

**Ключевой вывод:** ядро системы прочнее, чем её периферия. Бизнес-логика и серверная
авторизация подтверждены тестами; фронтенд, мобильный контур и деплой — нет.

## Critical Findings

### SEC-001 / BACK-001 — анонимный доступ к данным проекта через ИИ-эндпоинт

- **Severity:** `P1` *(понижено с P0 после эмпирической проверки — обоснование ниже)*
- **Component:** `server.ts:2774`, `POST /api/ai/chat`
- **Статус:** `CONFIRMED` (анонимный доступ и утечка метаданных) ·
  `PARTIALLY CONFIRMED` (расход платного ресурса) ·
  `NOT VERIFIED` (утечка содержимого документов на текущих данных)

**Evidence.** Middleware chain пуст — обработчик вызывается сразу, без `requireAuth`,
`requireRole`, `requireProjectAccess` и без rate-limit. При пустом `documents` в теле:

```js
const docsToGround = Array.isArray(documents) && documents.length > 0
  ? documents
  : (projectDataStore['proj-1']?.documents || []);   // server.ts, +18 от начала обработчика
```

Далее, `server.ts:2802` — в промпт уходит **содержимое** документа, если оно есть:

```js
typeof doc.content === 'string' ? doc.content.slice(0, 4000) : (doc.title ? `${doc.title}. …` : …)
```

**Один controlled request** (clean-room, свежая БД, ключ GenAI намеренно не передан):

```
POST /api/ai/chat  {"message":"test"}   без заголовка Authorization
→ HTTP 200
→ is_fallback: true, ai_source: "local_rag"
→ в ответе присутствует название документа proj-1 («Рабочая документация …»)
```

**Attack Surface.** Неаутентифицированный HTTP POST. Требуется только сетевой доступ к серверу.

**Potential Impact.** Раскрытие метаданных документов проекта `proj-1` (название, код, ревизия,
статус, объём) анонимному вызывающему. Механизм способен раскрыть **до 4000 символов содержимого**
каждого документа, но в текущих демо-данных поле `content` отсутствует. Дополнительно —
потребление платного Google GenAI без аутентификации и без лимита.

**Reproduction Feasibility.** Тривиальная: один POST без заголовков. Воспроизведено фактически.

**Root Cause.** Маршрут спроектирован как публичный демонстрационный и не переведён в защищённый
контур. Жёсткая привязка к `proj-1` — остаток демо-логики.

**Recommended Fix.** `requireAuth` + `requireProjectAccess` по явному `projectId`; удалить
подстановку `proj-1`; добавить rate-limit.

**Regression Test.** Анонимный `POST /api/ai/chat` → 401; аутентифицированный без доступа к
проекту → 403; ответ не содержит данных проектов, к которым нет доступа.

**Почему P1, а не P0** (п.5 задания — отсутствие auth само по себе не делает находку P0):
подтверждённая утечка ограничена **метаданными одного документа демо-проекта**. Это не
`material data exposure`, не компрометация системы и не катастрофический финансовый эффект.
Утечка содержимого структурно возможна, но на текущих данных не воспроизведена. Расход платного
ресурса в контролируемом запросе не состоялся — сработал локальный fallback.
При заполнении поля `content` реальными документами приоритет подлежит пересмотру до `P0`.

### SEC-002 — анонимное потребление платного внешнего API

- **Severity:** `P1` · **Component:** `/api/ai/analyze-document`, `/api/ai/daily-report`
- **Статус:** `CONFIRMED` (отсутствие auth и лимитов) · `NOT VERIFIED` (фактический расход)
- **Evidence:** middleware chain пуст, `requireAuth: false`, `rate-limit: false`,
  путь к GenAI через `AiResilience`; `analyze-document` дополнительно защищён circuit breaker.

  проектов не читают — работают только с телом запроса, поэтому утечки нет.
- **Recommended Fix:** `requireAuth` + rate-limit.
- **Regression Test:** анонимный запрос → 401.

## Top 5 Risks

1. **Доказательная база компрометирована в мобильном контуре.** Фиктивное фото + тихая потеря
   дефекта + неработающая офлайн-очередь означают, что записи, созданные на объекте, могут не
   существовать в системе или содержать несуществующие доказательства. Для продукта, чья ценность
   в доказуемости, это подрывает основное назначение.
2. **Рассинхронизация типов носит системный характер.** Прецедент уже был исправлен точечно
   (`scripts/verify-mobile-defect-fields.mjs`), но тот же класс дефекта остался в 9 файлах.
3. **Развёрточный контур нерабочий в трёх независимых местах** — Docker, CI/CD и `.env`.
   Любая попытка развернуть систему сегодня провалится.
4. **Нет БД-уровня изоляции.** Один пропущенный вызов `requireProjectAccess` в будущем эндпоинте
   не будет ничем подстрахован.
5. **Роль TECHNICAL WRITER не выполнена** — расхождения документации с кодом не выявлены,
   при этом в корне лежат отчёты с заявлениями «Production-Ready», уже опровергнутыми.

## Top 5 Improvements

1. Привести 9 компонентов к фактической схеме `src/types/index.ts` — компилятор уже указал строки.
2. Ввести `tsc --noEmit` как обязательный CI-гейт вместо точечных guard-скриптов.
3. Закрыть периметр `/api/ai/*`: аутентификация + rate-limit.
4. Довести мобильную форму: `await` результата, убрать фиктивное фото, либо реализовать
   синхронизацию офлайн-очереди, либо убрать обещание синхронизации из интерфейса.
5. Привести `Sidebar` в соответствие с `can()`, уже используемым внутри самих экранов.

## Conflicting Findings

**CONFLICT-001 — критичность ролевого переключателя.**

- **UX/UI (агент):** `UX-001`, `P0` — «любой может стать SUPER_ADMIN одним кликом, рвётся цепочка
  ответственности». Сам агент пометил вывод о серверной стороне как `ПРЕДПОЛОЖЕНИЕ`.
- **Orchestrator (проверка факта):** `switchRole` (`AppContext.tsx:808`) не вызывает API и не меняет
  `authToken` — чисто клиентское состояние. Backend продолжает опознавать исходного пользователя
  по токену; тест на подмену личности заголовком проходит.
- **Разрешение:** реальной эскалации привилегий **нет**. Приоритет понижен `P0 → P2`.
  Остаётся как вводящая в заблуждение демо-функция, недопустимая в production.
- **Побочная находка при разрешении:** `logAction` (`AppContext.tsx:882`) — **пустая функция**
  `() => {}`, при этом вызывается по всему фронтенду. Загрязнения аудита не происходит именно
  потому, что аудит на клиенте не ведётся вообще. Заведено как `ARCH-006`.

**CONFLICT-002 — число вызовов синхронного API БД.**
Round 1 указал 72, фактически 94. Причина: Round 1 считал только `server.ts`. Принято **94**.

**CONFLICT-003 — читает ли `/api/ai/chat` данные из БД. РАЗРЕШЁН.**

- **Evidence A** — `.agent-state/BLOCKERS.md`, `BLK-004` (DISC-001):
  «ПРОВЕРЕНО: читают тело запроса, а не БД → межарендаторной утечки нет».
- **Evidence B** — DISC-002: строка подстановки `projectDataStore['proj-1']?.documents`
  при пустом `documents`; подтверждено контролируемым запросом — в ответе присутствует название
  документа `proj-1`.
- **Required Verification:** выполнена — один controlled request в clean-room.
- **Разрешение:** верно **Evidence B**. `BLK-004` содержал неверное утверждение.
- **Первоисточник ошибки найден:** `docs/security/VERIFIED_API_SECURITY_MATRIX.md:74` заявляет

- **Урок:** документ с названием `VERIFIED_` был принят за проверенный факт. Это ровно тот

**CONFLICT-004 — количество маршрутов.**
`grep -cE "^app\.(get|post|put|patch|delete)\("` → 76; программный разбор с одиночным строковым

## Ограничения этого discovery

Честная фиксация отклонений от п.2 спецификации:

- Роли **ARCHITECT, BACKEND, DATABASE, SECURITY, QA, E2E, DEVOPS** исполнены Orchestrator'ом на
  основе evidence, собранного в трёх раундах аудита этой сессии, а не независимыми агентами.
  Принцип независимой проверки (п.79) для этих доменов **не соблюдён**.
- Роли **FRONTEND, MOBILE/PWA, UX/UI** исполнены независимыми агентами.
- Роль **TECHNICAL WRITER** не выполнена (зависание).
- Первая попытка запуска (5 агентов) прервана лимитом API; результаты потеряны.

Следствие: security-выводы не проходили независимую верификацию. Для `SEC-001` это особенно
существенно — требуется подтверждение вторым исполнителем (п.79: исправляющий агент ≠ проверяющий).
